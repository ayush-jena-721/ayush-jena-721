# AYUSH OS — setup

## Install

```bash
# create a PUBLIC repo named exactly your username
git clone https://github.com/ayush-jena-721/ayush-jena-721.git
cd ayush-jena-721

# copy in: README.md  assets/  tools/  fonts/  data/  output/  .github/
git add .
git commit -m "AYUSH OS v7.2"
git push
```

Open `https://github.com/ayush-jena-721`. The boot sequence runs on every page load: black → power-on → boot log → terminal → reactor ignition → character materialisation → signature draw → role cycle → ambient. Roughly 8 seconds, then it settles.

| Where | What |
|:--|:--|

| `tools/mk_panels.py` → `MODULES` | module percentages are my read of your old README — set numbers you'd defend in an interview |
| `tools/mk_panels.py` → `PROJECTS` | add the real repo URL per project |

Then `python tools/build_all.py` and commit.

## Real data, no invented numbers

`tools/fetch_github.py` reads the GitHub GraphQL API and writes `data/contributions.json` and `data/stats.json`. `.github/workflows/hud.yml` runs it daily and on push, rebuilds the SVGs and commits them.

Until that first run, the matrix says **AWAITING FIRST SYNC** and the stat cards show `—`. That's deliberate. Nothing here fabricates a commit count, a star total or a contribution cell. The contribution levels are bucketed against your own non-zero quartiles, so the intensity scale reflects your account instead of an arbitrary constant.

To sync locally:

```bash
export GITHUB_TOKEN=ghp_...        # a classic token with read:user is enough
export GH_USER=ayush-jena-721
pip install pillow numpy scipy fonttools
python tools/fetch_github.py && python tools/build_all.py
```

The snake (`output/snake-*.svg`) is generated by `Platane/snk` in its own workflow. Those two files don't exist until it runs once — that block in the README will show a broken image until then. Run the workflow from the Actions tab straight after pushing, or delete the block if you'd rather not have it.

## Three constraints worth knowing

**Hover doesn't work.** The spec asks for hover reactions on the armor modules and the ID card. GitHub renders README images inside `<img>`, and images don't receive pointer events — no repo has ever managed it, because there's no mechanism to. Every hover interaction was rebuilt as a *timed* one instead: modules power on in sequence, the card scans on a loop, the reactor pulses. If you want true hover, host the SVGs on a page (GitHub Pages works) and embed them inline in HTML rather than through `<img>`.

**No JavaScript anywhere.** All motion is SMIL, CSS-free, plus SVG filters, masks, clipPaths and gradients. Everything is clipped to the rounded frame, including the scanner.

**Fonts are baked in.** `AYUSH JENA` is real vector path data extracted from Orbitron by `tools/typeset.py` — not a `font-family` reference, so it renders identically whether or not the visitor has the font. Body labels use the monospace stack and degrade gracefully.

## Cache busting

Every local image in the README carries `?v=20260829`. GitHub proxies images through its own cache; when you regenerate an asset, bump that string everywhere (a single find-and-replace) or the old frame keeps showing.

## On the theme

The visual language is armor-HUD, arc-reactor, holographic-lab. All of it is drawn from scratch in this repo — no studio logos, no film assets, no official branding, and I deliberately kept the trademarked character and company names out of the visible text, using **AYUSH OS**, **REACTOR CORE** and **EMITTER ARRAY** instead. It reads as *your* engineering OS rather than fan merchandise, and it's yours to publish, modify and put in a portfolio without a licensing question attached. If you want the trademarked names in there anyway, they're a search-and-replace in `tools/` — just know what you're putting on a public profile.
